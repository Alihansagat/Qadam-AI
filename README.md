# Qadam AI · 0.5

Рабочее пространство для владельца одного магазина: продажи, прогноз, план закупок, заказы поставщикам и анализ рекламных отчётов. Валюта — KZT, интерфейс — русский.

## Запуск

Нужен Node.js 24 или новее. Внешние npm-зависимости не нужны.

```sh
npm start
# http://127.0.0.1:5180
npm test
npm run build
```

Локальный сервер доступен только на 127.0.0.1. Данные сохраняются в `output/local.sqlite`; эта папка не публикуется. Локальный режим использует одного владельца `local-owner` и не отправляет сообщения Telegram. Сборка создаёт автономный Worker в `dist/server/index.js`, включает статические ресурсы и миграции.

## Первый запуск магазина

1. Откройте «Магазин и помощь», укажите название магазина (настройка этого браузера).
2. В «Импорт данных» скачайте пример CSV и подготовьте свою полную историю. До 5 000 строк и 1 МБ на файл; сериализованный запрос сохранения также ограничен 1 МБ, поэтому для длинных названий фактический предел может быть ниже.
3. Подтвердите полноту истории и загрузите файл. Ошибки блокируют применение всего набора. Успешная загрузка сохраняется на сервере и доступна после перезагрузки.
4. Сверьте выручку и остатки. В обзоре можно выбрать 7, 14 или 30 дней, найти товар и скачать продажи.
5. Проверьте прогноз и срок поставки, рассчитайте закупку под бюджет, создайте черновик заказа.
6. Согласуйте цену с поставщиком. Отправка Telegram требует отдельного подтверждения в интерфейсе. Оплату и получение отмечает владелец.

## Данные и восстановление

Обязательные колонки продаж: `date,sku,name,units,price,cost,stock,on_order,lead_days`.
Одна строка — один товар за завершённый день. Дни без продаж должны быть подтверждены и записаны с `units=0`. Для каждого товара нужна непрерывная история и одинаковая последняя дата. Учитываются последние остатки и товары в пути.

Загрузки продаж и маркетинга сохраняются раздельно, привязаны к вошедшему пользователю. Повтор одного набора не создаёт новую копию. История хранит до 100 разных снимков каждого типа; при достижении лимита сохранение отклоняется, данные не удаляются. Восстановление старой загрузки создаёт новую текущую версию без удаления истории. Конфликт между вкладками возвращает 409 и требует повторного чтения текущей версии.

В «Магазин и помощь» можно скачать JSON с текущими продажами, рекламой и всеми заказами. Это выгрузка для хранения, не механизм автоматического восстановления полной базы. Предыдущие снимки доступны через историю приложения. Демо открывается отдельно и не перезаписывает сохранённые продажи.

## Что изменилось в 0.5

- Подключены серверные загрузки, история и восстановление, включая раздел маркетинга.
- Исправлена сборка Worker: все зависимости сервера включаются в независимых областях видимости; миграции попадают в пакет публикации.
- Локальная SQLite применяет миграции, поддерживает атомарные пакеты записей.
- При недоступности хранилища нельзя создать исчезающий после перезагрузки заказ; есть повтор загрузки.
- Удалён личный контакт из формы поставщика. Загрузка данных не сбрасывает начатую форму заказа.
- Согласованы пороги истории: 7 дней — предварительное недельное среднее; 28 — выбор базовых методов; 42 — сравнение; 70 — отдельный тест.
- Исправлены подписи периода и фильтрация ассортимента после появления дополнительных таблиц.
- Добавлены первый запуск, справка, экспорт данных, предупреждение о старых остатках, адаптивное меню для телефона и более ясный интерфейс.

## Развёртывание и границы доступа

Идентификатор сайта сохранён в `.openai/hosting.json`. Публикация использует существующий приватный сайт и базу D1 с привязкой `DB`. Миграции перечислены в `drizzle/meta/_journal.json`.

**Сайт должен оставаться доступным только владельцу.** Текущая Telegram-интеграция использует общие настройки `TELEGRAM_BOT_TOKEN`, `OWNER_TELEGRAM_CHAT_ID`, общий offset и доверяет границе доступа Sites для вызовов планировщика. Открытая регистрация, публичный доступ и независимые Telegram-настройки разных организаций не поддерживаются. Заголовок `oai-authenticated-user-id` должен задаваться доверенным шлюзом Sites, а не клиентом.

Существующее расписание опрашивает ответы Telegram; его настройка не изменена. Тесты используют подставной Telegram и ничего не отправляют реальным получателям. Подключение и доставку на реальном поставщике нужно проверять отдельно с его согласия.

## Ограничения использования

Это инструмент аналитики и планирования для одного владельца, а не замена кассы, бухгалтерии или складской системы. Возвраты, налоги, комиссии, автоматические платежи, изменение остатков при получении заказа, многомагазинность и роли сотрудников не реализованы. Реклама загружается CSV, прямые рекламные и маркетплейс API отсутствуют. Название магазина хранится в браузере; настройки сценария бюджета, ручные методы, ML-отчёт и отметки плана действуют в текущей вкладке.

Прогноз отражает наблюдаемые продажи; акции и потерянный спрос не моделируются. Экономический эффект на реальном магазине ещё не измерен. До массового запуска нужен пилот на реальных данных и отдельная проверка процесса закупки.

## Проверки

`npm test` проверяет расчёты, короткую историю, бюджет, импорт, изоляцию владельцев, сохранение, дедупликацию, восстановление и конкурирующие обновления, статусы заказов, запрет повторной отправки, а также готовый Worker. Ручная браузерная проверка включает импорт, перезагрузку, прогноз, бюджет, сохранение черновика, маркетинг и мобильную навигацию.

Подробности обучения моделей и история предыдущих решений: `docs/ARCHITECTURE-0.4.md`; исторические ограничения в этом файле относятся к старой версии. Python ML-код в этом обновлении не менялся.
